# 一句话推荐项目

## 目标

把零散项目资料转成可直接转发、投资人能快速判断的融资项目推介。默认交付是带基础信息和 3–4 个亮点的正式转介稿，不是严格的一句话；只有用户明确要求最终产物为“一句话”“100字以内”或“朋友转发一句”时，才交付单句短消息。用户把本 skill 称作“一句话 skill”或类似名称，不构成切换为单句输出的指令。

首触达材料的首要任务，是在事实边界内让目标投资人愿意约一次聊聊；完整建立投资确信属于后续 BP、会议和 DD 任务。先判断转发场景与希望推动的下一步动作，再决定证据顺序和文风。

## 首要原则：投资判断压缩

投资判断压缩、冲击力与性感度优先于证据完整性。推介稿只保留能让投资人快速形成判断的事实与强推断；产品规格、客户导入过程、地点、合同条款、完整计算和保密凭证进入 BP 或 DD。压缩不等于逐字复述，也不等于夸大：数字、客户状态和预测身份必须准确，但投资结论可以比原材料更锋利。

### Teaser 的进攻边界

首触达不是审计报告。不要把材料改写成谨慎摘要；用硬事实做锚点，主动提炼最能制造关注与约谈欲望的投资结论。按三层处理：

1. **事实锚点**：材料或用户明确提供的数据、客户状态、产品进度、验证周期、团队履历；必须准确归属。
2. **进攻性推断**：允许基于多条事实推出材料未逐字写出的结论，例如由性能代差、已进入头部客户和较长验证门槛推出“形成数月级先发窗口”。结论不必是审计口径，但创始人必须能在 30 秒内讲清证据链。
3. **空洞口号**：删除“弯道超车、行业遥遥领先、技术深厚、未来潜力巨大”等没有比较口径、客户价值或投资含义的形容词。

唯一标准是：**事实可追溯、推断可辩护、结论有投资含义。** “无法证伪”本身不构成质量；模糊到无法证伪的句子通常没有信息量。结论应当因为证据链强而难被反驳，而不是因为措辞含混而无法检验。

以 `3秒理解机会 → 5秒产生兴趣 → 15秒能够复述` 为准：

- **3秒**：这是什么级别的机会？
- **5秒**：为什么公司正在跑出来？
- **15秒**：凭什么相信增长可持续、值得约谈？

每条信息进入主文案前，判断：是否改变“值不值得看”的投资判断；是否能被非行业读者一句话理解；是否提供新证明而非运营细节重复。任一答案为否，移入 BP/DD 或删除。

默认面向通用投资人而非行业工程师。赛道吸引力、公司势能和一条硬商业证明通常优先于技术稀缺性；技术、流程和参数只能输出为已消化的投资结论，如“独有检测技术”“性能提升 68 倍”，不得输出原始型号、工程参数或过程细节。

### 3/5/15 内容映射

在写稿前，先识别项目正在从什么状态走向什么状态，再在后台确定且只选一条：

- **3秒资产标签**：投资人应记住的机会类别；
- **5秒势能证明**：公司正在跑出的最硬事实，以及相对过去发生的关键变化；
- **15秒复述句**：外部红利如何传导为客户需求、公司兑现和持续增长。

每个亮点必须服务其中至少一项；无法进入这三项的信息不占主文案。不得把材料中需行业解释的专业术语、客户地点、型号或流程原样搬到主文案；“半导体”“先进封装”等通识赛道词除外。

项目标题只承担 **3 秒资产标签**，不要同时塞入订单、增长或团队判断。各亮点依次回答不同问题，全文共同完成 **5 秒兴趣** 与 **15 秒复述**；不得要求第一亮点同时解释赛道与公司势能。

### 信息优先级

按“能否驱动约谈”而非“资料是否详尽”取材：

1. **一级｜机会**：赛道窗口、供需缺口、政策或产业拐点、可核验的市场规模；只回答“市场为什么值得看”。
2. **一级｜势能与商业验证**：收入/合同/订单增长、头部客户采购、复购、复制、量产或规模拐点；只回答“公司是否正在跑出来”。
3. **二级｜资格与客户价值**：性能突破、技术路线、产品平台、效率/成本/质量结果；先翻译成客户为什么买，再翻译成投资人为什么值得投。
4. **三级｜复利与兑现**：数据、网络、跨品类复制、团队履历、资质与交付记录；必须有已发生证据，不能用能力形容词代替。
5. **四级｜工程与材料细节**：产品型号、精确技术参数、零部件名、客户基地/城市、导入流程、样品数量、验证周期、文件来源；首触达推介一律不写，留在 BP/DD。

项目标题从机会类别中提炼资产标签。亮点顺序按证据强弱决定，但机会、势能、资格、复利、兑现不能因“都很重要”而挤进同一段。

### 五类投资判断模块

- **机会**：赛道、供需缺口、结构性窗口；
- **势能**：收入、合同、订单、客户、量产或增长阶段；
- **资格**：技术性能、产品突破、行业位置；
- **复利**：平台、数据、闭环、复制与切换成本；
- **兑现**：团队、资质、交付、案例与融资阶段。

一个项目通常选择其中 3–4 个模块；每个模块只保留一个投资结论和 1–2 条决定性证明。不要求市场、技术、客户和团队平均出现；产品型号、客户地点或导入流程不得写入首触达成稿。

### 一段一问与证据独占

起稿前先列出 3–4 个投资人问题，并为每个问题分配一段，例如：

- 市场是否足够大或正在形成刚需？
- 公司是否获得头部客户和订单验证？
- 产品为什么更好，客户得到什么？
- 团队为什么有资格把事情做成？

严格执行：

1. **一段只回答一个问题。** 市场段证明赛道，不写合同；客户段证明商业验证，不重复市场规模；团队段证明履历，不顺手罗列研发、供应链、量产、交付等泛化能力。
2. **一条事实只有一个归属。** 起稿前制作“事实 → 唯一段落”表；同一订单、客户或性能数字不得跨段复用。
3. **标题不强制双结论。** `+` 只有在两部分属于同一条因果链时才可使用，例如“性能代差+平台扩张”；不得把独立问题拼成“千亿赛道+合同放量”或“产业老兵+工程兑现”。
4. **段落之间递进，不互相代写。** 机会、验证、产品、团队合起来构成投资故事，每段自身保持纯净。

### FAB-F 投资翻译链

产品、技术、平台或数据事实不得停在属性描述，按以下顺序压缩：

1. **F｜Feature 属性**：客观有什么，只写可核验事实或数据。
2. **A｜Advantage 优势**：相较替代方案为什么更好；允许从性能、进度、验证门槛和客户阶段中提炼“先发窗口、时间优势、替代资格”等强推断。
3. **B｜Benefit 客户利益**：明确帮助客户增收、降本、提效、提质或降风险。可做紧贴产品机理的因果推断，但不得捏造客户已经实现的量化结果。
4. **F｜Fundability 投资价值**：说明该客户利益如何转化为更强采购理由、复购、复制、毛利、规模增长或竞争壁垒。

每段不必机械写出四个字母，但必须同时回答“客户得到什么”和“这对投资人意味着什么”。市场段可将客户需求作为 B、市场容量作为投资价值；团队段只允许从具体履历推导已被事实证明的兑现优势，证据不足时停在履历，不补“兼具全链条能力”等空话。

### 首触达模式

- **投资人朋友转介**：从五类模块中选择最易转述的 3–4 个独立问题，按“机会 → 验证 → 产品/团队”递进；写得像懂行朋友转发，而不是项目方自述。
- **FA 定向推介**：用主判断定义机会，再用势能、资格、复利或兑现模块建立可信度，最后给出融资与对接动作。
- **项目方正式介绍**：仍以投资判断领衔；仅在用户明确需要公司介绍或材料缺乏交易证据时，才扩大产品和技术说明。

融资完成通常只作阶段信号；除非投资方或交易本身构成已核实的独立背书，不得替代客户、订单、收入或交付等商业证明。

## 正式推介的叙事框架库

读取 [references/narrative-patterns.md](references/narrative-patterns.md)，从四套完整的成交叙事中选取起点、证明顺序和可用模块。不要按行业套模板；它们不是行业分类，也不是互斥模板：一个项目可以采用某套结构的主线，并借用其他结构中真正由证据支持的模块；不得为了“套全模板”增加弱亮点。

唯一固定的是交易逻辑：前三分之二必须让投资人看见已发生的证明与下一阶段的可推演路径。先用五类判断模块决定“机会、势能、资格、复利、兑现”中谁领衔，再用框架库安排顺序。市场、技术、团队、订单、资质、案例和资本的顺序，应由项目最强证据和希望消除的疑虑决定。不要在成稿中露出框架名称。

## 工作流

1. 先通读全部资料，建立事实底稿：基础信息、公司已实现业绩、订单与客户、技术与产品、市场数据、团队履历、资本背书、未来预测。
2. 完成 3/5/15 内容映射，从机会、势能、资格、复利、兑现中选出最能驱动约谈的 3–4 个独立问题。读取 [references/narrative-patterns.md](references/narrative-patterns.md)，只用它安排段落顺序，不把相邻节点合并成一段。
3. 建立“问题 → 段落 → 独占事实”表。发现两段使用同一事实，或一段回答两个问题时，先重分配再起稿。默认输出 3 个亮点，只有第四个问题证据独立且足够强时才增加。
4. 按投资判断链排序。第一亮点只回答最强问题：若赛道窗口最强，就只讲机会与需求；若订单最强，就只讲商业验证。技术不能因资料丰富而领衔。
5. 按 FAB-F 写段落：**标题=单一问题的投资结论；正文=属性/事实 → 相对优势 → 客户利益 → 投资价值。** 每段只用 1–2 条独占证明；事实允许向上提炼一层强推断，但不得凭空增加精确数字、客户结果或绝对排名。
6. 对每个强推断做“30 秒答辩”：能否立刻指出支撑事实、说清推导关系、解释客户和投资人分别得到什么？不能则改写或删除。
7. 完成后逐项核对事实归属、段落去重、客户利益、投资价值、时间、单位、已实现/预测状态、最高级表述及输出卫生，再交付成稿。

## 真实单句的例外

只有用户明确要求最终产物为一条短消息时，才暂停正式转介稿结构并输出单段纯文本；不得添加 `## 一句话转介` 等标题。单句仍优先使用“当前变化 → 商业证明 → 增长逻辑 → 轻 CTA”，但不应影响默认完整推介稿。

## 默认输出格式

默认严格沿用以下骨架，不增加 Markdown 标题、前言、方法说明或泛泛总结。用户已提供具体格式时，以用户格式为准；项目定位标题可选，基础信息与项目亮点为必备主体：

```text
【融资项目—{一句话定位}】（可选）

■ 基础信息
所在地：{城市}
赛道：{赛道1、赛道2}
融资轮次：{轮次}
融资金额：{金额与币种}
交易结构：{可选；仅资料提供时保留}

■ 项目亮点
一、【{8–16字的结论型小标题}】
{只回答一个投资人问题；用 1–2 条独占事实完成“属性 → 优势 → 客户利益 → 投资价值”，通常70–120字。技术能力只能以消化后的结论表达；不得以产品型号、精确参数、零部件/测试对象、客户地点或导入流程作为证明。}

二、【{8–16字的结论型小标题}】
{正文}

三、【{8–16字的结论型小标题}】
{正文}
```

首行只可为项目定位标题或 `■ 基础信息`，不得附带文件名、材料名或来源。基础信息只保留所在地、通俗赛道、融资轮次和融资金额；不写“非首轮”等不能改变投资判断的交易琐事。赛道应是投资人易懂的行业类别，不以产品型号、工艺、部件或检测对象堆砌。

基本信息未提供时省略该字段；若用户需要完整模板，则写“待补充”，绝不猜测。用户明确偏好其他标题样式时，可将标题改为 `【{定位}】` 或 `【{定位}推介——{公司简称}】`。

## 写作规则

- 项目标题只写 3 秒资产标签，不叠加订单、客户、团队或增长判断。亮点标题写成该段唯一问题的投资结论。
- 不强制双结论标题。只有“属性/事实 → 直接结果”属于同一因果链时才可用 `+`；市场+订单、团队+工程、技术+客户验证等跨模块拼接一律拆段。
- 每段只论证一个核心问题；删除重复卖点、形容词串和无法改变投资判断的信息。同一事实只在一段出现一次。
- 优先使用硬证据，但不追求硬证据数量。每段仅保留一至两条最能改变投资判断的事实锚点，再提炼一个可辩护的进攻性结论；其余事实进入 BP/DD。
- 原始事实必须按 FAB-F 做投资翻译：先写客观属性与相对优势，再明确客户获得的增收、降本、提效、提质或降风险，最后写该利益如何带来采购、复购、复制、毛利、增长或壁垒。只说“形成闭环”“越用越强”“平台化空间”而未说明客户和投资人分别得到什么，视为未完成。
- 团队段只写可核验的机构、职位、年限、成果或奖项。禁止用“兼具研发、工程化、供应链与规模交付能力”“整建制兑现”“全链条能力”等概括性能力串收尾，除非每项都有独立事实且共同回答同一问题。
- 明确时间口径，例如“2025年实现”“2026年预计”“截至2026年5月”；预测数字必须带“预计/目标/规划”，不得写成既成事实。
- 保留用户给出的币种与量级，统一同一篇内的格式。可写 `1亿元`、`3,000万元人民币`，不要把 `10000万`机械照抄为不自然表达。
- 默认写成紧凑段落，不在亮点下再拆 1、2、3 级列表，除非用户明确要求。
- 默认控制在约 300–550 个汉字；用户明确要求更完整时再扩展。证据多时宁可删弱信息，也不要写成 BP 摘要。
- 保持投资人口吻：在证据边界内使用最强可辩护结论，短句、证据密集；只有明确时序或对比证据显示加速时才写“爆发”“放量”等变化性判断，不用“扎实”“深厚”“全面”等形容词替代证明，也不使用“颠覆一切”“无限想象空间”“绝对领先”等无证据口号。
- “领先、先发、窗口、卡位、替代资格、平台扩张”等投资结论可以不是材料原句；只要能由事实链推出并通过 30 秒答辩，就应大胆使用。时间型结论如“数月级先发窗口”必须有产品阶段、客户进度或验证周期支撑，但不要求材料提供同一句原文。
- 在朋友转介模式中，优先让读者知道“这是什么机会、公司现在发生了什么”；只保留“半导体”“先进封装”等投资人普遍理解的行业通识，不保留 `Chiplet`、探针卡等需行业解释的技术名词。技术能力改写为通俗投资结论。
- 正式转介稿的第一项亮点必须是最强的单一投资问题；若第一段讲市场规模，就不得同时写公司合同或订单。“基础信息”是资料索引，不等于叙事开场。
- 交付前做一次“红笔删减”：删去行业外读者难以复述的专业名词、不能改变判断的工程过程、重复证明、融资花絮，以及“领先、扎实、深厚、全面、持续兑现、想象空间”等没有新增事实的形容词。

## 事实与合规护栏

- 不编造，不联网补齐项目数据，除非用户明确要求调研；外部调研数据必须标明年份并可追溯。
- 严格区分公司业绩与团队历史。写“创始人曾带领……”“团队过往累计……”；不得改写成“公司已实现……”。
- 严格区分收入、在手订单、意向订单、框架协议、签约客户、付费客户、验证客户和合作伙伴；结论应在事实边界内向上提炼，但不得将合同、订单、复购或待交付偷换成已确认收入或业绩。
- 严格区分样机、验证、导入、小批量、量产和商业化；不得擅自抬高阶段。
- `第一`、`唯一`、`首个`、`最大`、`龙头`、`领军者`等最高级，仅在资料明确且存在可支撑口径时使用；否则降级为“领先”“第一梯队”“少数具备……的企业”。
- 市场规模、增长率、估值、回本周期等计算必须有基数与时间边界；信息不足时删掉，不能倒推。
- 对脱敏公司名、客户名、金额或其他遮罩原样保留，不还原、不猜测。
- 若原材料存在冲突，尤其融资轮次、融资金额、收入/合同额或客户状态冲突时，不得静默择一或用较早材料覆盖用户最新的明确表述；采用可核实的带时间戳口径，或写“待确认”，并在成稿后追加不超过 3 条“口径提醒”。
- 首触达推介一律不得出现：产品型号（如 `FS606`）、精确技术参数（如 `0.293μm`）、零部件/测试对象名（如“探针卡”）、客户基地或城市名（如“苏州、南通”）、导入过程、样品量、验证周期。它们即使真实且有利，也只能留在 BP/DD。
- 不得在正式推介稿中输出源文件名、页码、OCR 残片、内部材料标识、分析过程或工具痕迹；成稿出现 `.pdf`、`.ppt`、`.doc` 等文件扩展名即视为不合格，必须删除。

## 交付前检查

- 项目标题是否只完成 3 秒资产标签，而没有夹带第二个投资问题？全文是否可拼成 15 秒复述句？
- 是否已建立“问题 → 段落 → 独占事实”表，并确认每段只回答一个问题？
- 市场段是否只讲机会，客户/订单段是否只讲验证，团队段是否只讲履历与成果？
- 每个强结论是否紧跟至少一个事实或数字？
- 每个进攻性推断能否通过 30 秒答辩：事实锚点是什么、推导为何成立、投资含义是什么？
- 公司、团队、行业、预测四类事实是否归属正确？
- 全文数字、年份、单位、融资轮次是否前后一致？
- 是否可直接复制转发，无需用户再删解释性文字？
- 标题是否为投资判断，而非事实标签、产品型号、客户地点或导入流程？
- 读者能否在 3 秒理解机会类别、5 秒看到公司跑出的证明、15 秒复述“机会 + 证明 + 持续性”？
- 是否已在后台明确 3秒资产标签、5秒兴趣点和15秒复述句，并让每个亮点承担不同问题？
- 每个亮点是否严格控制为一个问题、一至两条独占证明？
- 产品/技术段是否完成 FAB-F：写清属性、优势、客户利益与投资价值？

- 是否清除了源文件名、页码、OCR 残片、内部材料标识和分析过程？
- 若删除公司名，这段文字是否仍像一条清晰的机会判断，而非一组项目方形容词？
