# 一句话推荐项目

## 目标

把零散项目资料转成可直接转发、投资人能快速判断的融资项目推介。默认交付是带基础信息和 3–4 个亮点的正式转介稿，不是严格的一句话；只有用户明确要求最终产物为“一句话”“100字以内”或“朋友转发一句”时，才交付单句短消息。用户把本 skill 称作“一句话 skill”或类似名称，不构成切换为单句输出的指令。

首触达材料的首要任务，是在事实边界内让目标投资人愿意约一次聊聊；完整建立投资确信属于后续 BP、会议和 DD 任务。先判断转发场景与希望推动的下一步动作，再决定证据顺序和文风。

## 首要原则：投资判断压缩

投资判断压缩与冲击力、简单短平信息优先于证据完整性。推介稿只保留能让投资人快速形成判断的事实；产品规格、客户导入过程、地点、合同条款、完整计算和保密凭证进入 BP 或 DD。压缩不等于夸大：所有保留的数字、客户状态和预测身份仍须准确。

以 `3秒理解机会 → 5秒产生兴趣 → 15秒能够复述` 为准：

- **3秒**：这是什么级别的机会？
- **5秒**：为什么公司正在跑出来？
- **15秒**：凭什么相信增长可持续、值得约谈？

每条信息进入主文案前，判断：是否改变“值不值得看”的投资判断；是否能被非行业读者一句话理解；是否提供新证明而非运营细节重复。任一答案为否，移入 BP/DD 或删除。

默认面向通用投资人而非行业工程师。赛道吸引力、公司势能和一条硬商业证明通常优先于技术稀缺性；技术、流程和参数只能输出为已消化的投资结论，如“独有检测技术”“性能提升 68 倍”，不得输出原始型号、工程参数或过程细节。

### 3/5/15 内容映射

在写稿前，先识别项目正在从什么状态走向什么状态，再在后台确定且只选一条：

- **3秒资产标签**：投资人应记住的机会类别；
- **5秒势能证明**：公司正在跑出的最硬事实，以及相对过去发生的关键变化；
- **15秒复述句**：外部红利如何传导为客户需求、公司兑现和持续增长。

每个亮点必须服务其中至少一项；无法进入这三项的信息不占主文案。不得把材料中需行业解释的专业术语、客户地点、型号或流程原样搬到主文案；“半导体”“先进封装”等通识赛道词除外。

项目标题必须承担 **3 秒资产标签**；第一亮点及其前两句必须完成 **5 秒势能证明**，并能与后文拼成 **15 秒复述句**。写稿前先完成这三项，未通过则不得起稿。

### 信息优先级

按“能否驱动约谈”而非“资料是否详尽”取材：

1. **一级｜机会与势能**：赛道窗口、收入/合同/订单增长、头部客户采购强度、量产或规模拐点；优先识别项目“从 A 到 B”的变化，用于项目标题和第一亮点。
2. **二级｜商业验证**：客户结果、复购、复制、规模密度、单位经济性、准入或标杆案例；用于强化势能与可持续性。
3. **三级｜进入资格与复利**：性能突破、技术路线、平台、数据、闭环；只能先翻译成“高端替代资格、客户价值或持续性”，再作为证明使用。
4. **四级｜工程与材料细节**：产品型号、精确技术参数、零部件名、客户基地/城市、导入流程、样品数量、验证周期、文件来源；首触达推介一律不写，留在 BP/DD。

标题与第一亮点只能从一级或二级信息得出。三级信息不能抢占机会和势能的位置；四级信息没有“例外保留”。

### 五类投资判断模块

- **机会**：赛道、供需缺口、结构性窗口；
- **势能**：收入、合同、订单、客户、量产或增长阶段；
- **资格**：技术性能、产品突破、行业位置；
- **复利**：平台、数据、闭环、复制与切换成本；
- **兑现**：团队、资质、交付、案例与融资阶段。

一个项目通常选择其中 3–4 个模块；每个模块只保留一个投资结论和 1–2 条决定性证明。不要求市场、技术、客户和团队平均出现；产品型号、客户地点或导入流程不得写入首触达成稿。

### 首触达模式

- **投资人朋友转介**：从五类模块中选择最易转述的“机会 + 势能”或“资格 + 势能”组合，再给一条自然的约谈理由；写得像懂行朋友转发，而不是项目方自述。
- **FA 定向推介**：用主判断定义机会，再用势能、资格、复利或兑现模块建立可信度，最后给出融资与对接动作。
- **项目方正式介绍**：仍以投资判断领衔；仅在用户明确需要公司介绍或材料缺乏交易证据时，才扩大产品和技术说明。

融资完成通常只作阶段信号；除非投资方或交易本身构成已核实的独立背书，不得替代客户、订单、收入或交付等商业证明。

## 正式推介的叙事框架库

读取 [references/narrative-patterns.md](references/narrative-patterns.md)，从四套完整的成交叙事中选取起点、证明顺序和可用模块。不要按行业套模板；它们不是行业分类，也不是互斥模板：一个项目可以采用某套结构的主线，并借用其他结构中真正由证据支持的模块；不得为了“套全模板”增加弱亮点。

唯一固定的是交易逻辑：前三分之二必须让投资人看见已发生的证明与下一阶段的可推演路径。先用五类判断模块决定“机会、势能、资格、复利、兑现”中谁领衔，再用框架库安排顺序。市场、技术、团队、订单、资质、案例和资本的顺序，应由项目最强证据和希望消除的疑虑决定。不要在成稿中露出框架名称。

## 工作流

1. 先通读全部资料，建立事实底稿：基础信息、公司已实现业绩、订单与客户、技术与产品、市场数据、团队履历、资本背书、未来预测。
2. 先识别项目的关键变化或增长拐点，再完成 3/5/15 内容映射并按信息优先级筛选素材；再从机会、势能、资格、复利、兑现中选出最能驱动约谈的 3–4 个判断模块。读取 [references/narrative-patterns.md](references/narrative-patterns.md)，从其中选择最适合的叙事起点、证明顺序和模块组合。再提炼一个定位标题和 2–4 个可辩护的核心亮点；默认输出 3 个亮点，只有第四项证据独立且足够强时才增加。
3. 按投资判断链排序，而不是按原材料顺序堆砌。第一亮点默认连通“外部红利 → 客户需求 → 公司当期兑现”，完成“机会 + 势能”；仅当团队、政策、资质或标杆案例本身比商业势能更能驱动约谈时才例外。技术不能因资料丰富而领衔。
4. 按固定段落语法写：**标题=投资判断；首句=通俗商业结论；次句=1–2 条最强证明；末句=该证明的投资含义。** 每段只保留一个判断；超过两条证明时，默认删减或移入 BP/DD。三级事实必须先翻译；四级事实一律不写。
5. 完成后逐项核对事实归属、时间、单位、已实现/预测状态、最高级表述及输出卫生，再交付成稿。

## 真实单句的例外

只有用户明确要求最终产物为一条短消息时，才暂停正式转介稿结构并输出单段纯文本；不得添加 `## 一句话转介` 等标题。单句仍优先使用“当前变化 → 商业证明 → 增长逻辑 → 轻 CTA”，但不应影响默认完整推介稿。

## 默认输出格式

默认严格沿用以下骨架，不增加 Markdown 标题、前言、方法说明或泛泛总结。用户已提供具体格式时，以用户格式为准；项目定位标题可选，基础信息与项目亮点为必备主体：

```text
【融资项目—{一句话定位}】（可选）

■ 基础信息
所在地：{城市}
赛道：{赛道1、赛道2}
融资轮次：{轮次}
融资金额：{金额与币种}
交易结构：{可选；仅资料提供时保留}

■ 项目亮点
一、【{8–16字的结论型小标题}】
{先写投资判断，再给 1–2 条决定性证明，最后翻译其商业含义；通常70–120字。技术能力只能以消化后的结论表达；不得以产品型号、精确参数、零部件/测试对象、客户地点或导入流程作为证明。}

二、【{8–16字的结论型小标题}】
{正文}

三、【{8–16字的结论型小标题}】
{正文}
```

首行只可为项目定位标题或 `■ 基础信息`，不得附带文件名、材料名或来源。基础信息只保留所在地、通俗赛道、融资轮次和融资金额；不写“非首轮”等不能改变投资判断的交易琐事。赛道应是投资人易懂的行业类别，不以产品型号、工艺、部件或检测对象堆砌。

基本信息未提供时省略该字段；若用户需要完整模板，则写“待补充”，绝不猜测。用户明确偏好其他标题样式时，可将标题改为 `【{定位}】` 或 `【{定位}推介——{公司简称}】`。

## 写作规则

- 把项目标题和亮点标题写成投资判断，优先回答“这是什么机会、公司为何值得看”；项目标题优先组合“3秒资产标签 + 5秒势能判断”，避免空泛的“优质项目”。
- 亮点标题可采用“机会判断+公司势能”“竞争资格+商业验证”“规模占位+复利路径”或“高准入+客户结果”等结构；产品参数、客户地点、导入流程及其改写版都不得进入标题或正文。
- 把亮点小标题写成双结论，如“千亿蓝海+业绩爆发”“行业第一+规模占位”；两个短语必须由正文证据支撑。
- 每段只论证一个核心判断；删除重复卖点、形容词串和无法改变投资判断的信息。
- 优先使用硬证据，但不追求硬证据数量。每段仅保留一至两条最能改变投资判断的证明；其余事实进入 BP/DD。
- 原始事实必须先做投资翻译：订单与客户采购证明公司势能；性能突破证明高端替代资格；产品矩阵证明平台化空间。翻译后仍不能改变投资判断的，不上主文案。不得以“客户在哪个基地导入、采用什么部件、哪个型号、精确到何种参数”补充证明。
- 明确时间口径，例如“2025年实现”“2026年预计”“截至2026年5月”；预测数字必须带“预计/目标/规划”，不得写成既成事实。
- 保留用户给出的币种与量级，统一同一篇内的格式。可写 `1亿元`、`3,000万元人民币`，不要把 `10000万`机械照抄为不自然表达。
- 默认写成紧凑段落，不在亮点下再拆 1、2、3 级列表，除非用户明确要求。
- 默认控制在约 300–550 个汉字；用户明确要求更完整时再扩展。证据多时宁可删弱信息，也不要写成 BP 摘要。
- 保持投资人口吻：在证据边界内使用最强可辩护结论，短句、证据密集；稳定兑现可写“扎实”，只有明确时序或对比证据显示加速时才写“爆发”“放量”等变化性判断，不使用“颠覆一切”“无限想象空间”“绝对领先”等无证据口号。
- 在朋友转介模式中，优先让读者知道“这是什么机会、公司现在发生了什么”；只保留“半导体”“先进封装”等投资人普遍理解的行业通识，不保留 `Chiplet`、探针卡等需行业解释的技术名词。技术能力改写为通俗投资结论。
- 正式转介稿的第一项亮点必须是最强投资判断；“基础信息”是资料索引，不等于叙事开场。
- 交付前做一次“红笔删减”：删去行业外读者难以复述的专业名词、不能改变判断的工程过程、重复证明和融资花絮。若已有更强的订单、客户或业绩证明，则删除同一结论下的技术过程佐证。

## 事实与合规护栏

- 不编造，不联网补齐项目数据，除非用户明确要求调研；外部调研数据必须标明年份并可追溯。
- 严格区分公司业绩与团队历史。写“创始人曾带领……”“团队过往累计……”；不得改写成“公司已实现……”。
- 严格区分收入、在手订单、意向订单、框架协议、签约客户、付费客户、验证客户和合作伙伴；结论应在事实边界内向上提炼，但不得将合同、订单、复购或待交付偷换成已确认收入或业绩。
- 严格区分样机、验证、导入、小批量、量产和商业化；不得擅自抬高阶段。
- `第一`、`唯一`、`首个`、`最大`、`龙头`、`领军者`等最高级，仅在资料明确且存在可支撑口径时使用；否则降级为“领先”“第一梯队”“少数具备……的企业”。
- 市场规模、增长率、估值、回本周期等计算必须有基数与时间边界；信息不足时删掉，不能倒推。
- 对脱敏公司名、客户名、金额或其他遮罩原样保留，不还原、不猜测。
- 若原材料存在冲突，尤其融资轮次、融资金额、收入/合同额或客户状态冲突时，不得静默择一或用较早材料覆盖用户最新的明确表述；采用可核实的带时间戳口径，或写“待确认”，并在成稿后追加不超过 3 条“口径提醒”。
- 首触达推介一律不得出现：产品型号（如 `FS606`）、精确技术参数（如 `0.293μm`）、零部件/测试对象名（如“探针卡”）、客户基地或城市名（如“苏州、南通”）、导入过程、样品量、验证周期。它们即使真实且有利，也只能留在 BP/DD。
- 不得在正式推介稿中输出源文件名、页码、OCR 残片、内部材料标识、分析过程或工具痕迹；成稿出现 `.pdf`、`.ppt`、`.doc` 等文件扩展名即视为不合格，必须删除。

## 交付前检查

- 标题是否完成 3 秒资产标签，第一亮点前两句是否完成 5 秒势能证明，全文是否可拼成 15 秒复述句？
- 标题和第一亮点是否只由一级或二级信息驱动？
- 每个强结论是否紧跟至少一个事实或数字？
- 公司、团队、行业、预测四类事实是否归属正确？
- 全文数字、年份、单位、融资轮次是否前后一致？
- 是否可直接复制转发，无需用户再删解释性文字？
- 标题是否为投资判断，而非事实标签、产品型号、客户地点或导入流程？
- 读者能否在 3 秒理解机会类别、5 秒看到公司跑出的证明、15 秒复述“机会 + 证明 + 持续性”？
- 是否已在后台明确 3秒资产标签、5秒势能证明和15秒复述句，并让每个亮点服务其中至少一项？
- 每个亮点是否严格控制为一个判断、一至两条证明和一句商业翻译？
- 是否将技术、流程和参数改写为投资人可复述的通俗结论，并删除其原始细节？
- 是否只保留“独有检测技术”“性能提升 68 倍”这类结果性表述，而未保留型号、精确工程参数或技术过程？
- 是否彻底删除产品型号、精确参数、零部件/测试对象、客户基地/城市、导入流程、样品量和验证周期？
- 是否清除了源文件名、页码、OCR 残片、内部材料标识和分析过程？
- 若删除公司名，这段文字是否仍像一条清晰的机会判断，而非一组项目方形容词？
