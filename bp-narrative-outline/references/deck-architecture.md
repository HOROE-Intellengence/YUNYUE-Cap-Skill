# Deck Architecture

## 架构节点

先定义页面为什么存在，再决定页面怎么画：

```text
P{N}
页面功能：
投资问题：
看前认知：
证据增量：
看后认知：
依赖页面：
优先级：胜负手 / 重要 / 可将就
覆盖六问：
```

普通证据页只选择一个职责：放大回报上限、降低失败概率或制造投资紧迫性。目录、竞争力地图和章节过渡承担建立认知框架；融资页承担推动交易行动。投资亮点总览是四类组合证据的明确例外。

删除不改变投资判断、不改善理解路径、也不推动下一步行动的页面。

## 页面职责与页面模式解耦

- 页面职责回答“本页为何存在”。
- 页面模式回答“这组证据如何被看懂”。
- 同一职责可以使用不同模式；同一模式也可服务不同职责。
- 不在 Architecture 阶段锁定构图、色彩或美术材料。

## 默认投资确信骨架

按证据自由增删和换序：

| 阶段 | 页面功能 | 投资作用 |
|---|---|---|
| 定调 | 封面 / 投资结论 | 定义为什么值得投 |
| 总览 | 投资亮点总览 | 用四个证据钩子建立兴趣 |
| 机会 | 为什么是现在 | 证明产业拐点与窗口 |
| 机会 | 市场天花板 | 放大回报上限 |
| 框架 | 核心竞争力地图 | 预埋论证结构 |
| 验证 | 项目能力沿革 | 证明时间沉淀成资产 |
| 验证 | 资本市场对标 | 证明相邻资产被重估 |
| 定位 | 未被占据的位置 | 解释竞争错位 |
| 进攻 | 产品楔子 | 证明如何切入 |
| 进攻 | 优势量化 | 翻译客户价值 |
| 防守 | 复利护城河 | 证明追赶越来越难 |
| 放大 | 商业模式 / 平台路径 | 证明如何放大 |
| 证明 | 客户、订单、收入、认证 | 降低商业化风险 |
| 想象 | FA 上行情景 | 展示可推演上限 |
| 终局 | 对标成长路径 | 说明最终形态 |
| 兑现 | 团队 | 证明关键能力覆盖 |
| 行动 | 融资 | 说明融资额与用途 |

## 排序检查

- 前五页满足“五秒规则”，但不强制固定目录。
- 成长路径双证据若成立，尽量相邻呈现。
- 依赖事实应先于推导结论；总览可以先亮结论，后续必须兑现。
- 整套 deck 覆盖投资委员会六问；缺口进入诊断与待补清单，不阻断输出。
