# 输入与证据契约

## Fact Ledger

先将材料拆成可追踪事实，不直接从原文跳到页面文案。

| 字段 | 规则 |
|---|---|
| `fact_id` | 使用稳定短编号，如 F01 |
| 陈述 | 保持原始含义，不先写成营销话术 |
| 主体归属 | 公司 / 创始人或团队历史 / 合作方 / 行业 / 预测情景 |
| 来源与日期 | 文件、页码、报告、合同、访谈或数据库；未知则标待补 |
| 单位与口径 | 币种、含税状态、周期、地域、累计/当期、签约/确认收入等 |
| 数字身份 | 事实 / 推断 / FA上行情景 / 待研究 |
| 置信度 | 高 / 中 / 低，并写明降低置信度的原因 |
| 保密状态 | 可公开 / 匿名展示 / 仅尽调披露 / 禁止对外 |

主体归属不可混用：团队过往业绩不能写成当前公司业绩；合作方能力不能写成公司自有能力；目标和预测不能写成已实现结果。

## Claim–Evidence Graph

为每个可能改变投资判断的主张记录：

```text
claim_id：C01
主张：
投资作用：放大回报上限 / 降低失败概率 / 制造紧迫性
支持事实：F01, F04
反证与边界：
证据强度：强 / 中 / 弱
状态：可上片 / 需降级表达 / 待补 / 仅DD
待补动作：
```

证据强度参考：

- **强**：可核验的一手经营、客户、产品、认证或交易材料，口径完整。
- **中**：可信二手来源、可复算推断或匿名但可在 DD 验证的材料。
- **弱**：单方口述、口径缺失、过时信息或只能说明相关性。

弱证据可以支撑研究假设，不能伪装成已确认结论。

## 数字身份纪律

- `[事实]`：已验证，保留来源和日期。
- `[推断]`：由事实计算，保留关键假设、公式和口径。
- `[FA上行情景]`：有条件的进攻性目标，保留实现路径。
- `[待研究]`：决定叙事但尚缺严谨证据。

页面只在事实与预测可能混淆时显示身份；后台和 DD 必须保留。跨页重复数字必须统一，或显式标注约数、不同周期、不同地域或 FA 测算。

## 掩码与关系

- 匿名、区间、占位符和掩码原样保留，不根据上下文猜测客户、金额、地点或机构。
- 使用高校、实验室、企业或 Logo 前核实真实关系。
- 不用连续线、Logo 排列或措辞暗示未经证实的技术转让、官方背书或机构隶属。
- 主张“同一技术底座连续演进”时，点明继承的具体资产。
