# Investor Attention and Content Compression

Treat investor attention as the scarcest resource on the slide. The outline is a candidate evidence pool, not a requirement to render every module, subpoint, label, icon, and product.

## Contents

- Default attention budget

- Copy rules

## The three-second test

An investor should understand these within three seconds:

1. what the slide concludes;
2. which number, comparison, mechanism, or object proves it;
3. why that proof matters to the investment case.

If several competing conclusions remain, choose the one that most changes valuation upside, failure probability, timing, or the project's right to win. Demote or remove the rest.

## Rank facts before layout

Classify every candidate fact silently:

- **A — decision-changing proof:** verified revenue, orders, customers, adoption, market size, technical performance, cost advantage, qualification, capability accumulation, or team evidence that changes the investment judgment.
- **B — necessary explanation:** one mechanism, assumption, boundary, or comparison needed to interpret an A fact correctly.
- **C — supporting inventory:** product lists, feature lists, secondary credentials, geography lists, implementation detail, repeated examples, generic claims, and evidence already proven elsewhere.

Build the page from A facts. Use only the minimum B facts required for interpretation. Omit C facts from the slide; retain them in source material, notes, appendix, or DD.

Factual accuracy does not require factual completeness on one slide.

## Default attention budget

Unless a page-mode exception applies, enforce:

```text
1 investor conclusion
1 memory anchor
2–3 evidence groups
1 decisive fact per evidence group
0–1 necessary supporting detail per group
0–1 optional bottom verdict, only if it adds a new implication
1 compact source or status line
```

Also enforce these ceilings:

- no more than three dominant numbers on a standard page;
- no more than one hero image, one coherent diagram, or one product family as the visual center;
- no more than 3–5 nodes in a standard mechanism or progression;
- no more than one icon per evidence group unless a precise comparison requires repetition;
- no more than two visible hierarchy levels inside a normal evidence group;
- no duplicate conclusion in headline, subtitle, center slogan, and bottom band.

Prefer two strong evidence groups over four weak ones. Use four only for the explicit four-card highlight mode. Use five only for a deliberately navigational Argument-map with one short line per entry.

## Compression operations

Apply these operations before reducing type size or adding containers:

1. **Delete** facts that do not change the investment judgment.
2. **Deduplicate** repeated claims, numbers, products, and implications within the slide and across the deck.
3. **Synthesize** several related facts into one assertion plus one representative proof.
4. **Select** one representative product, customer case, metric, or stage instead of displaying the full inventory.
5. **Demote** methodology, calculation detail, qualifications, and secondary proof to a compact source or status line.
6. **Move** confidential evidence, full calculations, product catalogues, and diligence detail to DD or appendix.
7. **Split** the page only when two independent investor conclusions are both essential and cannot be subordinated.

Never preserve overloaded input by shrinking copy, multiplying cards, creating nested containers, or adding rows of small icons.

## Copy rules

- Write the headline as one investor conclusion, not a topic label.
- Remove decorative English translations, redundant subtitles, chapter labels, and slogans unless the brand system or audience requires them.
- Use short claim labels rather than sentences inside cards.
- Put the decisive number next to the claim it proves; do not repeat it elsewhere.
- Prefer a number plus its meaning over several descriptive adjectives.
- Keep status markers and units attached to the relevant claim.
- Use one bottom verdict only when it advances the implication beyond the headline.
- Instruct the image model to render only the supplied on-slide copy and not invent additional microcopy.

Do not confuse simplicity with generic minimalism. Preserve the minimum proof needed to make the conclusion credible.

## Exceptions

### Investment-highlight-grid

Use exactly four cards, but keep each card to one hook and at most one proof line or status line. Do not add nested subcards, feature lists, or multiple icons.

### Argument-map

Allow 3–5 equal entries because the page is navigational. Each entry gets one short investment meaning, not its proof stack.

### Rigorous-comparison

Allow the repeated rows needed for a fair comparison, but show only 3–5 decision-relevant criteria. Move exhaustive specifications to appendix or DD.

### Technical mechanism

Allow up to five causal nodes when each node is necessary to explain the result. Remove component inventories that do not change the mechanism.

### Team

Allow one concise credential chain per key person. Prioritize role, unique right-to-win credential, and complementary coverage; omit biography trivia.
